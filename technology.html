Cloud-native storage

Read only what the question needs.

Location data is large: years of hourly mobility, imagery, millions of places and road segments. Loading it all for every question is what makes traditional GIS slow.

GeoParquet stores vector data in columns and row groups, each with a bounding box. A query for one catchment skips every row group outside it and every column it does not need.

Zarr stores rasters and time-series as compressed chunks across space and time. A five-kilometre catchment over one week touches a handful of chunks, which can be read in parallel straight from object storage.

Move the pointer over the grid: each square is a chunk, the dashed circle is a catchment query, and only the highlighted chunks are read.

The hexagonal grid

One grid that every dataset joins on.

We index everything — people, places, roads, imagery, mobility — to Uber's open-source H3 grid. Hexagons have six equidistant neighbours, so distance-based calculations have no edge or corner bias, and two datasets join on a cell ID instead of an expensive geometric intersection.

Each resolution nests inside the coarser one, so a metro-wide scan can run at a coarse level and refine only where it matters.

H3 resolutionEdge lengthAreaUsed for
7≈ 1.2 km≈ 5.2 km²Metro-wide screening
8≈ 460 m≈ 0.74 km²Whitespace pockets, market summaries
9≈ 175 m≈ 0.11 km²Neighbourhood profiles, coverage
10≈ 66 m≈ 0.015 km²Site scoring, trade-area boundaries
Why not squares or postcodes? Square grids have two kinds of neighbour and distort distance; administrative units vary wildly in size and change over time. Hexagons are uniform, stable and comparable across cities.

Model development

Iterate locally. Deploy to the cloud.

Forecasting models are developed in PyTorch, which lets us build networks around the structure of location data — tabular features alongside the spatial context of a trade area.

Prototyping runs on high-memory Apple Silicon with Apple MLX, where unified memory holds large feature sets without shuffling data to a GPU. Once an architecture proves itself, it is trained at scale and deployed to the cloud for inference.

Prepare once

Imagery, land cover and terrain are composited and summarised per hexagon in Google Earth Engine, then exported as analysis-ready layers.

Assemble features

Deploy and version
